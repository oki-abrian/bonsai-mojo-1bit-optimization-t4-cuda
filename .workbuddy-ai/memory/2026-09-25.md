## Gabungan S-CPFE + EoRA dalam satu micro-patch (converter MLX)

Konteks: `references/converter-mxfp4-backfree-sparse-test-full-graph/` (git-ignored
`.gitignore:26` — perubahan TIDAK masuk GitHub). User meminta S-CPFE dan EoRA
digabung "biar jangkauan neuron lebih lengkap". Cakupan gabungan = 5 situs:
MLP gate/up/down (EoRA) + gate atensi (`attn.sparse_gate_attn`) + out_proj GDN
(`ssm.sparse_out`) — dua situs terakhir khas S-CPFE.

### Kontrak fit berurutan (inti perbaikan)

- **Masalah**: `sparse_down` (S-CPFE) dan `eora_down` (EoRA) sama-sama difit ke
  sisa `y_fp16 − y_mxfp4`. Dipasang berdua tanpa koordinasi = koreksi dobel
  untuk kesalahan yang sama → akurasi bisa TURUN.
- **Solusi**: EoRA difit DULU, lalu S-CPFE difit terhadap sisa SETELAH EoRA
  (`_q_forward` di blok S-CPFE sudah memuat koreksi EoRA). Blok EoRA
  dipindah ke SEBELUM blok S-CPFE (perpindahan murni, diverifikasi:
  `Counter(lama) == Counter(baru)`).
- Urutan runtime yang dikontrakkan (lihat `EoraPerLinearMLP`/`SparseMLP`):
  `inter = silu(gate+Δg)·(up+Δu)`, `y = down(inter) + Δd(inter) + sparse_down(inter_elite)`.
  Regresor sparse per_linear = intermediate YANG SUDAH dikoreksi; mode e2e =
  intermediate mentah (koreksi e2e hanya di keluaran).
- Flag baru `--eor-with-scpfe {on,off}` (bawaan **on**; off = EoRA saja,
  perilaku lama). Berlaku hanya saat `eor_rank > 0`; `eor_rank == 0` tetap
  S-CPFE standalone, byte-identik.

### Bug runtime yang ikut diperbaiki (2 konsumen)

- `test_nrm_gen.py` + `benchmark_paper_metrics.py`: `SparseMLP` membungkus
  bungkus EoRA tapi mengambil `gate/up/down_proj` MENTAH dan tidak pernah
  memanggil bungkus EoRA → koreksi EoRA ter-bypass diam-diam pada patch
  gabungan. Kini cabang baru `perlinear`/`e2e` (deteksi lewat penanda
  `_eora_kind`) menerapkan EoRA + sparse dalam satu jalur. Jalur lama
  (patch tanpa EoRA) tidak berubah.
- `benchmark_paper_metrics.py` `SparseMLP.__init__` juga memakai
  `orig.gate_proj` langsung (akan crash untuk bungkus e2e) → kini `getattr`.

### Dua sisi EoRA (dikerjakan sebelumnya sesi ini)

- `--eor-targets mlp` (bawaan) = down_proj + gate_proj + up_proj (6 kunci:
  `eora_gate/up/down.A/B`); `down` = sisi keluar saja; `gate_up` = sisi masuk
  saja; `all` = sama dengan mlp. Help teks lama salah, sudah dikoreksi.
- Pergeseran kovariat diperbaiki: kovarians `down_proj` dihitung dari
  intermediate hasil koreksi gate/up, bukan intermediate mentah — kalau tidak,
  kedua koreksi saling menimpa.

### Status verifikasi

- `py_compile` + cek struktur AST lulus untuk `convert_mxfp4_optimized.py`,
  `test_nrm_gen.py`, `benchmark_paper_metrics.py`.
- **Belum diverifikasi numerik** — MLX tidak terpasang di mesin lokal mana pun
  (managed python, system python, homebrew) dan sesuai aturan jangan memasang
  toolchain berat di lokal. Validasi nyata = jalankan converter + benchmark di
  lingkungan MLX user.
- `debug_probe.py` TIDAK dibenahi (di luar cakupan yang disepakati): hanya
  membaca kunci `sparse_*`, jadi dengan patch gabungan kunci EoRA akan
  diabaikan diam-diam di sana.

### Cara pakai

`python convert_mxfp4_optimized.py ... --eor-rank 32 --eor-mode per_linear
--eor-targets mlp` (gabungan aktif otomatis; `--eor-with-scpfe off` untuk EoRA
saja). Patch keluar: `scpfe_patch.safetensors` berisi kunci EoRA + S-CPFE
(sparse_down + sparse_gate_attn + sparse_out per layer sesuai ketersediaan).
