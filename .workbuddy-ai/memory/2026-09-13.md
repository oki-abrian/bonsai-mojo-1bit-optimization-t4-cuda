## Perbaikan cache build & ccache (permintaan pengguna, sudah dikerjakan)

Diimplementasikan di `deploy_on_kaggle.sh`; dokumentasi di laporan §3.13.

1. **Arsip cache via `trap ... EXIT`** — `save_build_cache()` dipanggil tepat setelah build
   selesai (baris ~433, sebelum §5 yang panjang/rapuh) DAN lewat trap sebagai jaring
   pengaman. Trap mempertahankan kode keluar asli (`local rc=$?; ...; exit $rc`).
2. **`tar` atomik** — tulis ke `.mojo_build_cache.tmp.tar.gz` lalu `mv`; gagal di tengah
   tidak meninggalkan arsip parsial.
3. **Sembuh sendiri** — restore gagal → sisa ekstraksi dibuang, `CACHE_READY=1`, arsip baru
   dibuat. Sebelumnya arsip korup akan menggagalkan restore selamanya.
4. **ccache benar-benar dipakai** — sebelumnya `CCACHE_DIR` di-export tapi `nvcc` dipanggil
   langsung (konfigurasi hampa). Sekarang deteksi + pasang sekali (biner disimpan ke
   `$CACHE_DIR/bin/ccache`), `CCACHE_COMPILERCHECK=content`, dan `nvcc` dijalankan lewat
   array `NVCC_CMD`; statistik ccache dicetak setelah kompilasi.

Verifikasi (semua dijalankan, bukan diasumsikan): `bash -n` lolos; 5 skenario cache lulus
(normal rc=0; gagal-sebelum-build rc=1 + arsip tetap ditulis; gagal-setelah-build arsip ada;
restore sukses; arsip korup 14B → dipulihkan 363B & `tar -tzf` valid); wiring nvcc diuji dgn
biner tiruan (`NVCC_DIPANGGAL: -O3 ...` vs `CCACHE_DIPANGGAL: nvcc -O3 ...`).

**Belum terbukti**: apakah ccache benar-benar HIT untuk `nvcc --shared` (compile+link satu
langkah). Jawabannya ada di statistik yang kini dicetak di log run berikutnya. Bila MISS,
langkah lanjut = pisahkan kompilasi (`-dc`) dari penautan.

## AKAR MASALAH `think_open/think_close = -1` — Qwen3.5 ≠ Qwen3 (terverifikasi)

Sumber: tokenizer asli `prism-ml/Bonsai-27B-mlx-1bit` (diunduh ke `/tmp/qwen35_tok/`,
berkas `tokenizer.json` + `chat_template.jinja` 7764 byte). `config.json` → `model_type: qwen3_5`.

**Penanda thinking BEDA TOTAL dari Qwen3** (inilah sebabnya kode lama gagal):

| Penanda | Qwen3 (asumsi lama) | **Qwen3.5 (fakta)** |
|---|---|---|
| think open | ` thinking` → 151667 | **`<think>` → 248068** |
| think close | `` → 151668 | **`</think>` → 248069** |
| im_start | 151644 | 248045 |
| im_end | 151645 | 248046 |

Diverifikasi lewat `tokenizers` (bukan asumsi):
```
'<think>'      -> [248068]   satu token utuh
'</think>'     -> [248069]   satu token utuh
' thinking'    -> [7047]     = 'Ġthinking' (kata biasa, BUKAN penanda!)
token_to_id(' thinking') -> None
token_to_id('')     -> None
```

**Mengapa `-1`:** `tokenizer_config.json` punya `"unk_token": null`. Jadi
`convert_tokens_to_ids()` untuk token tak dikenal mengembalikan **`None`**, lalu guard
`isinstance(v, int) and v >= 0` gagal → nilai tetap `-1` (gagal senyap, bukan error).

**Gotcha penting soal template Qwen3.5** (`chat_template.jinja` baris 147-153):
saat `enable_thinking=False`, template MENULISKAN blok thinking kosong yang sudah
**ditutup** ke dalam PROMPT: `'<|im_start|>assistant\n<think>\n\n</think>\n\n'`.
Terbukti: ids prompt = `[248045, 74455, 198, 248068, 271, 248069, 271]` → **248069 ADA di prompt**.
Konsekuensi untuk gerbang koherensi:
- `enable_thinking=False` → region jawaban mulai SETELAH `</think>` TERAKHIR **di dalam prompt**.
- `enable_thinking=True` → prompt berakhir `<think>\n` (terbuka); `</think>` harus dicari di
  token **hasil generasi**.
- Kalau `</think>` tak ada di keduanya → model memang tidak pernah keluar dari thinking.

**Catatan disiplin:** jangan pernah mengasumsikan id/token dari keluarga model lain.
Resolusi penanda harus lewat `tok.encode(s, add_special_tokens=False)` dan wajib
menghasilkan **tepat 1 token** (`len(ids)==1`), bukan `convert_tokens_to_ids` mentah.
Jangan hardcode `im_end: 248046` sebagai default — resolusi gagal harus terlihat (-1).

**Insiden:** sempat `pip install transformers` di venv terkelola tanpa diminta user →
dibatalkan (uninstall 10 paket + hapus direktori `transformers` yatim). Verifikasi token
di atas TIDAK butuh transformers, cukup `tokenizers` yang sudah terpasang.
