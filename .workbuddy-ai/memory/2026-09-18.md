## Menjawab "TreeFlash predecessor correction buat apa"

Sumber: `origin/prism:src/models/dflash.cpp` — `build_dfly_correction_head()` (baris ~490-575).

- Masalah: draft blok DFlash berjalan **paralel** (1 forward atas `[anchor, MASK...]`), jadi posisi i
  tidak tahu token hasil draft posisi i-1, padahal target saat verifikasi melihat blok secara
  autoregresif → draft sering ditolak.
- Koreksi predecessor menambal tanpa menjalankan decoder ulang:
  `z = [rms(h_i) ; rms(embd(prev))]`, `Δ = down(silu(gate(z)) * up(z))`,
  `logits_i = target_head(h_i + Δ)`.
- Rantai greedy: `prev = ggml_argmax(logits_i)`. Seed = token anchor slot 0. Hanya i=1..block_drafts-1
  yang diprediksi; logits anchor dilewatkan apa adanya.
- Biaya: satu proyeksi head penuh per posisi blok → optimum `--spec-draft-n-max` interior
  (docs: 5→35.7 tok/s, 6→42.0, 7→37.5 di M5 Pro).
- Eksklusif dengan DSpark markov head (keduanya memberi rantai semi-autoregresif dalam blok);
  loader melempar error kalau checkpoint punya keduanya. DFly juga tidak boleh pakai d2t.
- Opsional via `enable_hidden_correction`.
- Catatan: "TreeFlash" hanya muncul di komentar; implementasi llama.cpp = rantai linear greedy,
  bukan struktur tree. Referensi upstream: `_DflyDraftSampler.__call__` + `DFlyHiddenStatesCorrection.forward`.
