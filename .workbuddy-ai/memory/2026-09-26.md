## Riset GSQ & RCO (kuantisasi PTQ, IST-DASLab) — verifikasi ke sumber primer

User menempel teks (kemungkinan keluaran AI lain) tentang "GSQ" dan "RCO" lalu minta
dicari di internet. Hasil verifikasi: **kedua metode NYATA**, tetapi **penamaan dan
beberapa klaim di teks itu salah**.

### Yang benar

- **GSQ = Gumbel-Softmax Quantization** (bukan "Gradient-based Scale Quantization" /
  "Global Scale Optimization"). Paper: arXiv:2604.18556, "GSQ: Highly-Accurate
  Low-Precision Scalar Quantization for LLMs via Gumbel-Softmax Sampling"
  (Dadgarnia, Tabesh, Nikdan, Helcig, Kurtić, Kleinegger, Alistarh; ISTA/DASLab).
  Kode: `github.com/IST-DASLab/GSQ`.
  Metode: init GPTQ (Hessian) → penyempurnaan logits grid dengan relaksasi
  Gumbel-Softmax (temperature 2.0→0.05, logit scale 100→500, optimizer Lion).
  Grid: integer **simetris** (ternary / 2-bit / n-bit), **group size bawaan 128**.
  Keluaran kompatibel GGUF K-Quant & kernel INT `compressed-tensors`.
- **RCO = Riemannian Constrained Optimization** (bukan "Resource-Constrained").
  Paper: arXiv:2605.00649, "Model Compression with Exact Budget Constraints via
  Riemannian Manifolds" (Helcig & Alistarh). Kode: `github.com/IST-DASLab/RCO`.
  Isi: memilih 1 dari K opsi per tensor (bitwidth 2..8) dengan anggaran total
  dipatuhi **tepat** — kendala jadi manifold halus di ruang logit, tiap langkah
  Adam diproyeksikan ke bidang singgung, ditarik balik (retraction, pencarian
  biner), momentum dipindah (vector transport); forward diskrit Gumbel-STE +
  solver knapsack eksak. Klaim: setara/lebih baik dari EvoPress (kuantisasi) dan
  EvoESAP (pruning) tapi 3–16× lebih cepat. **Termasuk MoE expert pruning**
  (grup = expert, opsi keep/prune) — relevan dengan pertanyaan user soal MoE.

### Yang salah di teks yang ditempel

1. Kepanjangan GSQ dan RCO (lihat di atas).
2. GSQ **bukan** NVFP4/E2M1 dan bukan "skala per 16 elemen" — ini integer scalar
   (tipe GGUF IQ*/K-quant), group 128; NVFP4/E2M1 tidak dikonfirmasi repo.
3. "Bagian sensitif dipertahankan BF16/FP8" — mekanismenya: satu tipe kuantisasi
   **per tensor** dari K opsi (2..8 bit) di bawah anggaran ukuran. Yang BF16 hanya
   **vision projector (mmproj)** dan itu berkas terpisah.
4. "~3× lebih kecil" — nyatanya **4,6×** (IQ3_S 3,50 bpw / 11,8 GB vs BF16 53,8 GB).
5. "dijalankan di GPU Blackwell/Hopper" — artifak rilis berupa **GGUF standar**
   (jalan di llama.cpp/Ollama/LM Studio tanpa syarat Blackwell). Hopper kelas
   sm_90 hanya untuk *training* GSQ (repo: diuji H100; serving sm≥80).
6. "pustaka ISTA-DASLab / llm-compressor" — `llm-compressor` = proyek **vLLM**
   (`vllm-project/llm-compressor`), bukan IST-DASLab.

## Tindak lanjut: rencana user — 2B sudah dikompres, mau 2 script (converter + perbaikan akurasi)

Fakta kunci yang sudah diverifikasi dari sumber (dipakai untuk menjawab):

- **GSQ butuh model asli (BF16) sebagai target rekonstruksi.** Objektifnya
  `min ‖f(x;w̃) − f(x;w)‖²_F` per layer linear — `f(x;w)` = keluaran layer presisi
  penuh. Jadi sebagai *guru* model asli wajib ada. Model asli tidak perlu masuk VRAM
  sekaligus: satu layer pada satu waktu, hasil tiap layer di-offload ke device `meta`
  sebagai shard `.safetensors`.
- **Mode "perbaiki GGUF K-quant yang sudah dirilis" ada** (titik mulai = file K-quant
  yang sudah beredar; GSQ menyempurnakan penetapan grid diskrit lalu memproyeksikan
  kembali ke format K-quant yang sama; contoh Qwen3-8B Q2_K 50,03 → 56,28).
  **Tapi**: guru tetap model asli, dan **tidak ada flag CLI khusus** untuk mode ini di
  README (hanya dijelaskan di bagian hasil) → invokasi harus dirangkai sendiri.
- **Jangan dekuantisasi lalu kuantisasi ulang** dari file terkompresi: llama.cpp punya
  flag `--allow-requantize` dengan peringatan eksplisit "dapat menurunkan kualitas
  secara parah" (galat menumpuk).
- **Hardware**: repo GSQ hanya diuji Hopper (H100 sm_90); pelatihan juga jalan di Ada
  (L40S sm_89); serving butuh sm ≥ 80. **T4 (sm_75) tidak diuji** → di Kaggle T4
  statusnya belum terbukti.
- **Lisensi**: kedua repo publik **Apache-2.0** → boleh diadaptasi dengan atribusi.
- Alur repo: `run_quantize.py` (database per-tensor multi-bitwidth) →
  `rco_search_quant.py` (alokasi di bawah anggaran) → `run_build_checkpoint.py`
  (materialisasi: `--format fake-quant` atau `compressed-tensors`).
- Bahan yang sudah ada di converter kita (`convert_mxfp4_optimized.py`): bobot asli
  sebagai target, aktivasi kalibrasi per layer (`tmp_files`), simulasi kuantisasi
  (`temp_mlp`) + sisa `y_fp16 − y_quant`. Yang belum ada: gelung optimasi gradien atas
  penetapan grid/skala (bagian GSQ-nya).

## Pengecekan: nama pembulatan-berpelatihan di converter + status jalur Mojo 2-bit

User lupa nama metode pembulatan yang memakai pelatihan di script converter. Hasil cek:

- **Namanya AdaMeZO**, fungsi `apply_zeroth_order_adaround()`
  (`references/converter-mxfp4-backfree-sparse-test-full-graph/convert_mxfp4_optimized.py:1760`).
  Docstring: "kompensasi error kuantisasi tanpa Backpropagation (BP-Free) — Data-Aware
  AdaMeZO / TurboBoA (Zeroth-Order Adam)". Mekanisme (dibaca dari kode, L1967-1995):
  perturbasi `W ± ε·z` (z Gaussian, ε=1e-2) → dua sim kuantisasi → gradien zeroth-order
  `g = ((loss1-loss2)/(2ε))·z` → Adam (lr 1e-5, β 0.9/0.999) → bobot ditulis balik
  (`update_weight`, tanpa dithering) **sebelum** kuantisasi final.
  Loss = `compiled_qad_loss` (L1445): `mean|student-teacher| + 2·(1−cos)` antara keluaran
  layer terkuantisasi dan keluaran layer presisi penuh.
  Flag: `--zo-steps` (20), `--max-seq-len` (512), `--batch-size` (1), `--skip-adamezo`.
  Guard q_mode: `[mxfp4, nvfp4, nvfp6, nvfp6_hybrid, nvfp2, nvfp2_hybrid]`.
  Dataset kalibrasi: `Jackrong/Qwen3.5-reasoning-700x` + teks fallback.
- **GSQ belum ada di converter**: grep `gumbel` = 0 di semua berkas keluarga converter.
- Urutan pipeline (D4_LATTICE_PLAN.md): rotasi → **AdaMeZO** → refresh alpha →
  S-CPFE/EoRA → kuantisasi final.
- **Jalur Mojo 2-bit TIDAK punya tahap patch/pembulatan berpelatihan**: sisi Mojo hanya
  memuat pak jadi dari HF. Bukti status (CATATAN_IMPLEMENTASI_BONSAI2.md §10b/10c):
  kernel `okiabrian/bonsai-2bit-infer` v5 `COMPLETE` exit 0, `bits=2`, decode 64,3 ms/token
  (15,5 tok/s) dengan prefill fallback; setelah qmm WMMA v2 → prefill 11,03 ms/token
  (90,6 tok/s); keluaran 16 token koheren. Pak: `prism-ml/Ternary-Bonsai-2-27B-mlx-2bit`,
  basis Qwen3.8-27B, `{bits: 2, group_size: 128, mode: affine}`.
- Titik temu dengan GSQ: pak 2-bit kita = ternary `{−1,0,+1}` dengan group 128; GSQ punya
  codebook `"ternary"` `{−s,0,+s}` dan group size bawaan **128** → cocok secara codebook.
  Kalau nanti direfine, struktur pak yang harus dihormati: signs Hadamard (28.672 nilai,
  3 lebar), layout lane di bit `2i` (U32, 16 bobot/word), skala per 128.
- Dua jalur berbeda yang jangan dicampur: (a) Mojo/T4 = inferensi dari pak jadi,
  (b) MLX converter di `references/` = patch S-CPFE/EoRA + AdaMeZO (model NRM/mxfp4).

## Analisis rancangan: AdaMeZO vs GSQ vs patch (jawaban untuk user, semua INFERENSI)

- **AdaMeZO dan GSQ tumpang tindih**: keduanya berakhir pada variabel yang sama (kode
  integer + skala). GSQ bisa memilih ulang setiap nilai grid, jadi ruang hasil AdaMeZO
  sudah tercakup; sumbangan AdaMeZO bila GSQ ada = kualitas titik awal saja.
- **Patch tidak tumpang tindih**: menambah parameter di luar bobot; satu-satunya yang
  bisa melewati plafon bpw. Biaya ukuran per layer ≈ `hidden × patch_neurons` byte
  (8-bit) + `(2×intermediate + hidden) × rank × 2` byte.
- Nilai marginal: patch > GSQ > AdaMeZO (bila GSQ sudah ikut). Jadi **GSQ + patch**
  menangkap hampir seluruh keuntungan 3 metode.
- Urutan wajib: inisialisasi/AdaMeZO **sebelum** GSQ. Bila sesudah, AdaMeZO menggeser
  bobot melewati batas pembulatan dan merusak penetapan GSQ. Aturan fit tetap: tiap
  tahap difit terhadap sisa setelah tahap sebelumnya (pelajaran dari S-CPFE+EoRA).
- Untuk jalur Mojo 2-bit (pak beku `prism-ml`, T4 sm_75 belum terbukti untuk GSQ),
  AdaMeZO lebih tepat berperan sebagai **pengganti** GSQ, bukan tambahan.
- Setelan AdaMeZO kita sangat konservatif (20 langkah, lr 1e-5, satu probe acak per
  langkah) → varians tinggi; selisih kecil tidak bisa dipercaya tanpa A/B berulang.
  Ingat disiplin ukur proyek: drift antar sesi 5–7%, selisih <8% tak bisa dinilai.

## Status pelatihan 2-bit ternary (dicek 2026-09-26)

- **Belum ada pelatihan/penyempurnaan sisi bobot untuk pak ternary kita.** Pak dibuat
  penerbit (`prism-ml`) → bagi kita read-only: bisa dijalankan & diukur, tidak bisa
  diubah bobotnya.
- Sebab teknis: seluruh mesin pelatihan butuh **simulator kuantisasi** yang cocok
  codebook. Di keluarga converter, kata `ternary` = **0** (nol di semua .py dan .md) →
  tidak ada cara menghitung loss terhadap codebook `{−s, 0, +s}`.
- Yang sudah ada sebagai bahan: kontrak ternary `w=(q−1)s`, q∈{0,1,2}; U32 LE 16
  bobot/word, lane i di bit `2i`; skala F16 `[N, K/128]`; group 128.
- **Rotasi & signs ada di sisi AKTIVASI, bukan bobot** (CATATAN_IMPLEMENTASI_BONSAI2.md):
  `forward = H_B @ (signs * x) / sqrt(B)`,
  `inverse = signs * (H_B @ x) / sqrt(B)`; block 1024; signs dipilih menurut lebar
  masukan K (3 lebar, 28.672 nilai; `gate_proj`/`up_proj` berbagi, `in_proj_qkv`/
  `in_proj_z` berbagi). Tensor `.signs` (402 buah) di safetensors **tidak dipakai** —
  dibaca dari metadata `hadamard.json`.
  → Konsekuensi: simulator sisi bobot sederhana (ternary per 128); yang harus ditiru
  tepat adalah urutan di sisi aktivasi.
- Verifikator sudah ada (jalur 2-bit Mojo jalan di T4); gelung pelatihan (cache aktivasi
  per layer, loss L1+kosinus ke keluaran presisi penuh, optimizer) sudah ada di
  converter — yang kurang hanya quant-sim ternary-nya.
- Dua syarat bila nanti dilatih: hasilnya harus bisa (a) dikembalikan ke format yang
  dibaca Mojo (pak baru atau berkas patch), dan (b) diuji ujung-ke-ujung.

## Rantai lengkap (sintesis seluruh pembahasan hari ini — rujukan utama)

Tujuan: **menaikkan akurasi pak Bonsai-2 ternary** (8,6 GB, `{−1,0,+1}`, group 128,
signs+FWHT di aktivasi, base Qwen3.8-27B). Pak = read-only → hasil harus berupa pak
baru atau berkas patch yang bisa dibaca Mojo.

Guru untuk kalibrasi: **GGUF GSQ-RCO IQ3_S 11,8 GB** (base sama) → dibaca `gguf-py`
(`dequantize(data, qtype)`, kelas `IQ3_S`), didekuantisasi per layer (≈0,85 GB), dipakai,
dilepas; cache aktivasi dibuat sekali. Ralat: "setara fp16" hanya pada skor tugas yang
diukur (ppl 7,07 vs 7,05) → plafon siswa = mutu guru.

Rantai kerja (urutan fit = urutan pakai saat inferensi):
1. Guru (GGUF IQ3_S) → dequant per layer → cache aktivasi kalibrasi.
2. **Quant-sim ternary — BELUM ADA, ini penghalang tunggal.** Tanpa ini tidak ada loss,
   jadi AdaMeZO, GSQ, *dan* patch (yang juga butuh quant-sim) semuanya terhalang.
3. AdaMeZO = tahap **inisialisasi** (bukan penutup), karena ia dan GSQ berakhir di variabel
   yang sama → ruang hasil AdaMeZO tercakup GSQ. Nilai marginalnya paling kecil bila GSQ ada.
4. GSQ = keputusan diskrit grid + skala; paling kuat; butuh pelatihan orde-satu; T4 sm_75
   belum terbukti.
5. Patch S-CPFE + EoRA (+gate atensi, out_proj GDN) = satu-satunya yang bisa melewati plafon
   bpw, dengan menambah parameter. Kode sudah ada & sudah digabung (EoRA dulu, S-CPFE
   difit ke sisa setelahnya).
Aturan tunggal: **tiap tahap difit terhadap sisa setelah tahap sebelumnya**.

## Cara mengakses guru & menangkap aktivasi (dicek 2026-09-26)

  `gguf-py` (di references/llama.cpp-prism) → dekuantisasi ke array NumPy → `mx.array`.
  Dua pilihan: dequant per layer saat dipakai (disk 11,8 GB) atau dequant sekali ke

  forward = aritmetika biasa di MLX. Yang tak bisa dilewati: rekurensi GDN (48 layer)
  karena input `out_proj` lahir dari state rekurensi. Hasil dequant-fp16 tidak bit-identik
  dengan jalur llama.cpp (beda pembulatan, bukan beda model).
- **Teknik penangkapan aktivasi sudah ada di converter** (`convert_mxfp4_optimized.py`):
  pasang daftar cache pada modul (`layer.mlp._cache_list`,
  `layer.input_layernorm._attn_cache_list`,
  `layer.linear_attn.out_proj._ssm_out_proj_input_cache`) → jalankan forward nyata →
  gabung per layer → tulis safetensors per tugas (`.tmp_cache_*.safetensors`, kunci
  `layer_{i}`, `layer_{i}_attn`, `layer_{i}_ssm_out_proj_in`, L2244-2246) → hook dilepas
  (L2253). Pass fitting membaca `tmp_files` berkali-kali (skor + OLS).
- **Ukuran cache** (dimensi kita: hidden 5120, GDN 6144, 64 layer) ≈ 16,8 MB per layer per

  Penghematan mungkin: jalankan seluruh tugas kalibrasi sebagai satu batch dalam SATU
  forward pass (cache digabung pada axis 0) → bobot guru dialirkan 1×, bukan 20×.
- **Pemilihan neuron elite = diukur, bukan dipelajari**: skor `corr = Σ inter·residual` per
  neuron → `argpartition` top_k (kelipatan 64; MLP & SSM = patch_neurons/256; gate atensi 64)

## GSQ: tidak butuh kernel 2-bit MLX — dan KOREKSI soal "forward guru" (2026-09-26)

Bukti dari kode referensi IST-DASLab/GSQ (dibaca langsung, bukan ringkasan):
- `src/quantization/gumbel_quantizer_ternary.py` (108 baris): `forward()` mengembalikan
  bobot **KONTINU** `output = soft_mask * soft_sign * scale_per_col` (relaksasi
  Gumbel-Sigmoid), dan backward-nya **analitik** ditulis tangan di
  `GumbelSoftmaxFunction.backward` (baris 96-106: grad_mask_logits, grad_sign_logits,
  grad_scales via `scatter_add_`). Tidak ada packing bit, tidak ada
  `quantized_matmul`.
- `src/models/base.py::calculate_mse` (baris 444-453): target =
  `forward_with_quantized(batch, None)` di bawah `torch.no_grad()` (bobot ASLI),
  siswa = `forward_with_quantized(batch, quantized_weights)`; kedua-duanya lewat
  `LinearWeightHook` yang mengganti forward jadi
  `torch.nn.functional.linear(x, quantized_weight, bias)` — **matmul padat biasa**.
- Jadi yang dibutuhkan: matmul padat + autodiff (atau backward analitik yang sudah
  tersedia), bobot asli per-lapisan sebagai target, dan batch kalibrasi x.

**KOREKSI pernyataan saya sebelumnya**: "yang menghalangi adalah forward guru" SALAH
untuk metode per-lapisan. GSQ (dan AdaMeZO/patch di converter) membangun target
per-lapisan dari **bobot** asli × aktivasi kalibrasi — bukan dari menjalankan model
guru. Bobot guru sudah bisa dibaca lewat `teacher_gguf.py`. Forward guru hanya perlu
bila ingin menangkap aktivasi kalibrasi dari guru sendiri atau mengukur metrik
ujung-ke-ujung.

Detail porting yang harus diingat:
- Referensi mengikat RNG lewat state CUDA (`torch.cuda.get_rng_state` + `fork_rng`)
  agar noise forward == backward → di MLX/kurung autodiff lain harus menyimpan noise
  atau memakai seed tetap.
- Memori fitting per-lapisan (estimasi, belum diukur): bobot kontinu + 2 tensor logits
  + keadaan optimizer ≈ 8-9 GB untuk lapisan terbesar → muat T4 16 GB tapi ketat.
- `groupsize` referensi = skala per kolom-grup, sama dengan kontrak kita (128).
- Repo GSQ punya `src/models/qwen35.py` — arsitektur basis Bonsai-2 didukung.

memfit terhadap distribusi guru = ketidaksesuaian kovariat — persis cacat yang sudah
